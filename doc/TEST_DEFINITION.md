# 営業日報システム テスト仕様書

---

## 1. テスト方針

### テスト種別

| 種別      | 目的                                 | 対象           |
| --------- | ------------------------------------ | -------------- |
| APIテスト | エンドポイント単位の正常・異常系検証 | 全API          |
| E2Eテスト | ユーザーシナリオ単位の結合検証       | 主要業務フロー |

### 優先度定義

| 優先度 | 基準                                                   |
| ------ | ------------------------------------------------------ |
| High   | 業務上必須の機能、データ破壊やセキュリティに関わる検証 |
| Medium | 準正常系、ロール制御、入力バリデーション               |
| Low    | UIの補助的な動作、ページネーション等                   |

### テストデータ前提

## 7. E2Eテスト（業務シナリオ）

### E2E-001 営業担当者の日報提出フロー

**目的:** 営業担当者が日報を作成し、上長が閲覧・コメントするまでの一連の流れを検証する

| ステップ | 操作                                           | 期待結果                              |
| -------- | ---------------------------------------------- | ------------------------------------- |
| 1        | 田中がログイン                                 | ログイン成功、トークン取得            |
| 2        | 田中が日報を作成（顧客2件、problem・plan入力） | 201、日報ID取得                       |
| 3        | 田中が作成した日報を詳細取得                   | 200、入力内容が正しく返る             |
| 4        | 鈴木がログイン                                 | ログイン成功                          |
| 5        | 鈴木が日報一覧を取得                           | 田中の日報が一覧に含まれる            |
| 6        | 鈴木が田中の日報詳細を取得                     | 200、内容が確認できる                 |
| 7        | 鈴木がproblemにコメント投稿                    | 201、コメントが保存される             |
| 8        | 鈴木がplanにコメント投稿                       | 201、コメントが保存される             |
| 9        | 田中が日報詳細を再取得                         | commentsに鈴木のコメントが2件含まれる |
